The Tool Manager portal

Open http://<printer address>:5000. The portal adds, edits, renames and deletes your own tools, stores photos of them, shows which connector pins are free, and restarts Klipper when changes need loading. The screenshots below come from a test run with two example tools (Needle, PenPlotter) and placeholder photos.

Tool library

Every tool is a card: slot, type, outputs, materials, notes and photos. The chips at the top right show Klipper's state, the job state and the mounted tool. Built-in tools are read-only here; your tools have an Edit button.

Adding a tool

Press + Add a tool. The wizard's steps depend on the kind of tool: powered tools get all seven, passive tools skip Hardware and Limits, print-head clones skip Limits and Materials. Every kind gets Controls and Macros.

1. Tool – pick the kind (hot wire, needle/vibrating knife, other powered, passive, or a print-head clone), type a name and optional notes. Choosing a kind fills in safe starting values. The name is what G-code and slicers use: 2–24 letters, digits or _, starting with a letter.

2. Hardware – choose where the power comes from: a new pin (only free tool-connector pins are offered) or an existing PWM output the tool plugs into, such as the spindle ESC channel. An optional enable line adds a relay or driver-enable pin.

3. Limits – the power cap (a hard ceiling whatever the G-code asks), minimum and idle levels, the watchdog's maximum on-time, and the S value that means full power.

4. Materials – the presets you pick when starting a job (power, feed, Z offset), and the pre-job checklist shown before every job with this tool.

5. Controls – extra outputs and inputs the tool brings: a vacuum relay, a cooling fan, a servo, a lid switch. Leave it empty if the tool has none. The tool's main power output stays on the Hardware step.

Press + Add a control and answer the guide's questions. You describe what the control does; the portal works out which Klipper section that needs and shows the exact text it will write.

  1. Name and purpose. Lower-case letters, digits and _, such as needle_vacuum. G-code uses the name (SET_PIN PIN=needle_vacuum), so it must not match anything else in your config.

  2. Which way does the signal go? Rhino controls something on the tool, or the tool sends a signal to Rhino.

  3. What should Rhino do with it? Pick the closest match:

  1. Which pin? Only free tool-connector pins are listed. If myrhino/umbilical.json says what each pin is ("type": "logic" or "type": "mosfet"), pins that cannot do the job are greyed out. A switched power output, for example, cannot read a switch or drive a servo.

  2. How does it behave? The questions depend on step 3: active-low wiring and the state at power-up for a switch; the maximum level and PWM cycle time for a level or a fan; the heater and turn-on temperature for a heater fan; the pulse widths for a servo.

  3. Safety and shortcuts.

    • Switch it off whenever the machine is made safe (ticked by default): it goes off at the end of a job, on cancel, on a tool swap and on EMERGENCY_STOP.

    • If Klipper shuts down: switch it off (recommended), or leave it on for cooling.

    • Make macros for it creates NAME_ON / NAME_OFF (or NAME_SET, NAME_ANGLE) for job files and the console. They can be limited to only switch it on while this tool is mounted.

For a signal from the tool, the guide asks how it is wired. A switch to ground turns on the pin's pull-up; a sensor that drives the line needs none. It then asks what happens when the signal triggers and when it is released: show a message, pause the job (only while one is running), emergency stop, or run a command or macro.

Add control saves only a valid entry. A name that is already used, a pin that is taken, or two controls on one pin are refused, with the reason shown in the preview box.

6. Macros – G-code macros that belong to this tool: a test cut, a purge, a park move. They are written to custom_tools.cfg with the tool and removed with it. Macros your controls made are listed underneath.

Press + Add a macro:

  • Macro name – letters, digits and _. Klipper ignores letter case, so it is saved in capitals.

  • Purpose – one line. It becomes the macro's description:, so Mainsail shows it in the macro list and console autocomplete.

  • Only run when this tool is mounted – adds a check at the top. With another tool on the machine, the macro refuses with a message and runs nothing.

  • Macro – Klipper G-code and Jinja ({% if %}, {params.S}), exactly as in a [gcode_macro].

The box underneath shows exactly what will be written. Before saving, the portal parses the section the way Klipper does and compiles its template.

  • Refused: a name used by any macro or Klipper command (SET_PIN, home, PAUSE), G-code words such as M3 or G28, and template errors such as a missing {% endif %}.

  • Warned, not refused: SAVE_CONFIG, FIRMWARE_RESTART or M112 in the body; a command the portal does not recognise (usually a typo); and text after # or ;, which Klipper drops as a comment.

7. Review – the portal checks everything against your live Klipper config and tells you the slot the tool will get. Add up to six photos here, then Create tool.

Restarting Klipper to load changes

A new or changed tool is saved immediately but is not live until Klipper restarts. A yellow banner says so; press Restart Klipper when the machine is idle.

The banner lists what is waiting, newest last, whether the change came from the portal or the console. Changes made during a job are saved and queued. Only the restart waits, so it can never kill a job.

While a job is printing or paused, Restart Klipper is greyed out and the banner says why. It also shows the job itself:

  • the file name and a progress bar;

  • time elapsed and time left;

  • the clock time when a restart becomes possible;

  • while paused, how long it has been paused. The countdown stops during a pause.

Time left comes from the slicer's estimate for 3D prints. Laser, CNC and cutter files usually carry no estimate, so the portal works it out from the file progress, the same way Mainsail does, and says so. Very early in such a job it shows time left unknown until there is enough progress to estimate.

Restart automatically when this job finishes is off by default. Tick it and the portal restarts Klipper 30 seconds after the job completes or is cancelled, which leaves time for END_PRINT or CANCEL_PRINT to finish. If the job ends with an error it does not restart, so you can see what happened. The banner then explains why. A restart started anywhere else (Mainsail, RESTART_FOR_TOOLS) also clears the banner, because Klipper re-reads its whole config at every start.

The console commands (ADD_TOOLHEAD and the rest) are still refused during a job. They run a shell command, and Klipper waits for it, which would stall the job's G-code.

Editing a tool

Press Edit on the tool's card. You can rename it, change its power limits, add, change or remove materials, edit the checklist and notes, and manage photos. Press Save changes, then restart Klipper.

Scroll down for the checklist, notes and photos. x on a photo deletes it; Choose Files adds more. Photos are kept in ~/printer_data/rhino_data/images/, outside the config folder, so config backups stay small.

The edit window has three tabs. Settings holds everything above. Controls and Macros work exactly like steps 5 and 6 of the wizard. Their changes are saved with Save changes and are live after the restart.

Deleting a tool

In the edit window press Delete tool. The button changes to Click again to delete <name>; press it within 4 seconds to confirm. The tool's pins are freed and its photos removed. Restart Klipper afterwards.

Pins and outputs

Pins & outputs shows every tool-connector pin as Free, In use (config) with the file and section that uses it, or Reserved by a tool. The second table lists the outputs a powered tool can share and their idle levels.

On a phone

The portal works on a phone: the menu folds behind ☰, and the status chips scroll sideways in the top bar.
