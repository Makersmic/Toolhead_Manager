Install and first start

The Rhino's software comes as one release zip, rhino-config-<version>.zip, which holds the Tool Manager, the Portal and Rhino Studio. The first install goes in once by hand, from a menu on the host. After that, every update goes in from Rhino Studio, with no terminal and no Mainsail.

The host

The host is a Dell OptiPlex 7050 Micro running Debian 12, with Klipper, Moonraker and Mainsail installed through KIAUH. Its name on the network is rhino. The Raspberry Pi 3B it replaced keeps its SD card as a spare. Setting up a new host, from the BIOS to the first print, is written out step by step in docs/migrate-7050.md; read its section The move, Nov 3 before you start.

Only one host may talk to the controller board. To go back to the spare, shut the 7050 down, move the USB cables to the Pi and start it. Its SD card is unchanged.

The first install, from the menu

Before you start: nothing printing, and a print head (BlockOne or SwitchFly) mounted. The Z check after the first start homes Z, and only a print head can do that. You need the host's address and its login (pi).

  1. Copy the zip to the host. In Mainsail open Machine and press Upload, or copy it with scp. Check that the name is exactly rhino-config-<version>.zip; a browser sometimes adds (1).

  2. Log in to the host from PowerShell, Terminal or PuTTY:

    ssh pi@rhino.local

  3. Open the Rhino menu. Paste one line at a time, with your version in place of 1.9.18:

    cd ~/printer_data/config
    unzip -o rhino-config-1.9.18.zip -d ~/rhino-1.9.18
    bash ~/rhino-1.9.18/rhino.sh
    /==========================================================\
|             ~~~~ [ Rhino Tool Manager ] ~~~~             |
|----------------------------------------------------------|
| Installed version : 1.9.17                               |
| This folder has   : 1.9.18   (/home/pi/rhino-1.9.18)     |
| Portal            : running                              |
| Rhino Studio      : http://rhino.local:5001              |
|                    by name  http://rhinostudio.local     |
|----------------------------------------------------------|
| 1) Preview the install       (changes nothing)           |
| 2) Install / update from this folder                     |
| 3) Install a new zip  (unpack, preview, install)         |
| 4) Undo an install            (pick a backup)            |
| 5) Portal status and recent log                          |
| 6) Restart the portal                                    |
| 7) Health check  (before and after a move)               |
|                                                          |
| Q) Quit                                                  |
\==========================================================/
Perform action:

  4. Preview: option 1. It checks your login, the config folder, whether a job is running and whether port 5000 is free, then lists every step without changing anything. It ends with Dry run finished, or with STOPPED: and what to do.

  5. Install: option 2, then y. It asks for the password once and works through its stages, each ending in OK:

    • backs up the config folder to ~/rhino-backup-<date>;

    • copies the new files, never touching variables.cfg, variables.save, your positions (myrhino/positions.cfg) or the files the Portal writes;

    • keeps the SAVE_CONFIG section at the bottom of printer.cfg, and fixes /home/pi paths if your login is different;

    • starts the Portal at every boot, and serves Rhino Studio at http://rhino.local, http://rhinostudio.local and port 5001. Mainsail moves to port 8090, as a spare until it is removed.

    Afterwards the menu is always at bash ~/rhino-manager/rhino.sh.

First start

Open Rhino Studio at http://rhino.local (or http://rhinostudio.local, or the address with :5001; some Android phones need the address in numbers). With the print head still mounted:

  1. Restart Klipper from the banner, or Settings › Host, and wait for Ready. If Klipper doesn't accept the config, the message names the file and line.

  2. Answer which tool is mounted. The question appears on Control, and the top bar shows a confirm button until it is answered (see Rhino Studio at a glance).

  3. Run CHECK_TOOLHEADS in the console on Control. When the line starting rhino: says OK, the tools are loaded.

  4. Check Z before the first job. All three Z steppers use gear_ratio: 2:1. Home with the print head, move Z 10 mm and measure it, then Level the gantry (Bed › Configuration) and check your Z offset.

A good place to stop is after the preview (nothing has changed yet) or after the first start. Avoid stopping between the install and the first start.

Updating from Rhino Studio

Every later release goes in from Settings › Software (see Settings):

  • Update on the Rhino Tool Manager row downloads the newest release from GitHub onto the Rhino and installs it. Check now looks again.

  • Install from zip takes a zip you downloaded, for a Rhino without internet. Drop it on the panel: it is checked before anything happens, and nothing installs until you press Install.

Both are refused while a job runs. The install shows each step with a tick; the Portal restarts part-way, which is expected, and Studio reloads itself on the new version when it's done. Rhino Studio is in the same zip, so it updates with the Tool Manager. Your tools, photos, tuning, maintenance history and settings are kept. Restart Klipper afterwards if the banner asks.

Going back: Go back to … under the drop area installs the zip kept from the version before. If Studio itself won't open, the menu's option 4 lists the backups, previews the restore and asks first; anything added since is moved aside to ~/rhino-undone-<date>, not deleted. Option 7 is a health check that changes nothing, for before and after a move.

Never home Z with the laser, spindle or drag knife mounted. Homing Z brings the bed up to the tool. Their macros refuse to, and jobs end with the bed lowered to the safe park height, so X and Y can be homed after a restart without the tool touching anything.

Moonraker and the Portal let in only the addresses on the trusted list (Settings › Trusted addresses). Keep the Rhino on your home network: the Portal has no login of its own, and anyone on that list can add or remove tools. It can't run G-code, and it refuses to restart Klipper during a job.
