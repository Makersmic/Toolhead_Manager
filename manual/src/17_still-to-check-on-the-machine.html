Still to check on the machine

The automated tests can't move the machine, so each release is checked on it. Work through these in order, with a hand on the emergency stop; stop at any test that doesn't pass and note its number. The full plan, with what counts as a pass, is in docs/testing.md.

Install and start

  • A1 Install 1.4.6 with menu option 3 – the preview shows no STOPPED, and the portal answers on port 5000.

  • A2 FIRMWARE_RESTART with a print head mounted – Klipper ready, no config errors.

  • A3 The which toolhead is mounted? question appears; CHECK_TOOLHEADS lists every tool.

  • A5 The portal opens on port 5000, shows 1.4.6, and follows Mainsail's dark/light switch within 15 s.

Motion and homing

  • B1 Jog X and Y 100 mm and measure – 100 mm ±0.5. About 50 mm means a step setting is wrong: stop and report it.

  • B2 Jog Z 10 mm and measure – 10 mm ±0.1 (gear_ratio 2:1). Then Z_TILT_ADJUST.

  • B5 Cancel a print – the bed lowers to Z150 or more, X/Y home, the head parks at X551 Y381 without touching the frame.

  • B5b Cancel a laser job (new in 1.4.5) – laser and rail off, bed lowers, no X/Y homing, the head goes straight to X551 Y381. If X or Y starts homing, report it.

  • B6 Z travel (new in 1.4.3): home with BlockOne, G1 Z290 F600 – the bed stays clear of its mounts – then G1 Z300 is refused and nothing moves. If the bed touches a mount at Z290, stop and send the Z where it is 10 mm clear.

Homing guard and positions (new in 1.3.8 and 1.4.0)

  • A6 LightSaber mounted: Mainsail's Home All is refused with a message and nothing moves. Home X and Home Y work once the Y endstop is set for the LightSaber. BlockOne mounted: Home All homes as before.

  • C4 Restart with the bed parked, then swap: the console says homing X/Y lowered the bed 10 mm and the park height was updated; SET_Z_ZERO then shows the new height.

  • A7 RHINO_POSITIONS lists the positions and says they are inside the travel limits. Change park_x in myrhino/positions.cfg to 540, restart, cancel a print: the head parks at X540. Put it back.

Tool swaps

  • C1 Swap BlockOne to LightSaber – waits for 40 °C, lowers the bed, never homes Z.

  • C2 During a swap, unplug the umbilical – Klipper keeps running (the nozzle reads about −50 °C). Confirm while it is unplugged: Toolhead not detected; plug in, Check again. C5 With LightSaber mounted, 200 in the nozzle temperature box is refused.

  • C3 Start a BlockOne file with the laser mounted – refused, nothing moves.

Printing

  • D1–D3 Paper test, then a test cube with the Orca profiles: the PLA question closes when answered, 210/65 °C, a 120 mm prime line, a slow first layer, the bed parked and the head at X551 Y381 at the end (1.4.4). The first layer is laid at the paper-test height (fixed in 1.3.8).

SwitchFly materials and the end of a job (new in 1.4.6)

  • D4 Start a SwitchFly file – it waits on Path 2 (T1) material? with path 1 from the file shown; nothing moves after homing.

  • D5 The confirmation lists both paths and the path it prints from; Proceed heats, primes and prints.

  • D6 Start it again – Same as last time is the first button, also after FIRMWARE_RESTART.

  • D7 Cancel at the path question – the job shows cancelled, nothing heats.

  • D8 SWITCH_T1 by hand loads and purges with path 2's material (no PLA default); SWITCH_T0 MATERIAL=NYLON is refused and nothing moves.

  • D9 An item ticked switch off when made safe stays on after a normal finish (print and laser), and goes off on cancel.

The record follows the tool (new in 1.4.7)

  • D10 Swap SwitchFly back on after leaving it on path 2 – the selector turns to path 1 and G1 E5 feeds in.

  • D11 Restart, answer Yes – SwitchFly – nothing moves, path 2 still feeds in.

  • D12 Swap to BlockOne after SwitchFly path 2 – G1 E5 feeds in.

Set Z zero

  • E1–E2 SET_Z_ZERO with LightSaber or HotJoe – the buttons move the bed the amount shown, Bed down stops at Z290, SET moves nothing, and G1 Z5 F300 then lifts the tool 5 mm above the surface.

  • E3 Restart with the bed parked, run SET_Z_ZERO – the Bed position question; Yes – the bed doesn't move, X/Y home, then the Set Z zero window opens. Needs [force_move] enable_force_move: True (in toolchanger.cfg).

  • E4 Restart after moving the bed below Z150 – no question; home Z with a print head.

  • E6 After a CNC or drag-knife setup, swap to BlockOne and print – no X/Y shift.

Laser, CNC and drag-knife jobs

  • F1–F3 Laser at low power on scrap; a CNC air cut 10 mm above the stock first; a drag-knife test line. Run the first file from the LaserWeb settings in Slicer and CAM settings at low power.

  • F4 Pause and resume each tool type – the 10 mm lift clears the work, and the spindle is back to speed before it re-enters the cut.

  • Power values – tune every placeholder power and on-time on the real tools.

Emergency stop and backups

  • H1–H2 EMERGENCY_STOP with the focus dot on – laser off at once; with HotJoe – relay open, ESC quiet.

  • I1 Klipper-Backup shows your config files in GitHub again after removing the stray .git folder.

Settings to know

  • Idle timeout – add [idle_timeout] timeout: 1800 if you use the full ABS/ASA cooldown.

  • Connector pins – only PB1, PC0 and PC1 are free; list any other spare umbilical pins in myrhino/umbilical.json.

  • LEDFLASH takes about 1.35 s, which also delays the macros that call it (cancel, emergency stop).

Network settings (new in 1.4.8)

  • N1–N4 Read the network; power saving off with Keep, Undo now, and letting the 2-minute timer switch it back.

  • N5–N7 Rename, fixed address kept from the new address, and a wrong address that switches back by itself.

  • N8 Changes refused during a print.

PrusaSlicer on the Rhino (from Flathub since 1.5.2)

  • P0–P2 Install Flatpak once (sudo apt install flatpak), install the engine from Rhino Studio, Settings / Software, and check it runs over SSH without a screen.

  • P3–P6 Slice a part, check the Rhino's start and temperatures are in the file, a newer slice stops the older one (and its sandbox), and the same slice again comes from the cache.

  • P7 Slicing during a print: half the cores on a bigger host, refused on a Pi 3B; the print keeps going smoothly.

  • P8–P9 Updating the engine from Flathub, and going back to the version before.

Rhino Studio from the Rhino (new in 1.5.1)

  • S1–S3 The install names Studio's address; Studio opens at http://<pi>:5001 on a PC and a phone, with the Portal's tasks and tools; Mainsail still opens.

  • S4–S6 A change through the Portal is accepted, the camera shows, and a job reaches Files.

  • S7 Undo takes Studio's site away again and leaves Mainsail working.
