Settings

Settings has three groups. The pages under Machine and System change the Rhino for every screen; Appearance is shared too, except the day-or-night choice, which is for the screen you're on.

Appearance

Look follows this device, or holds it to Dark or Light. Theme picks the colours every screen shares. Your own themes can have a background picture (Add picture…, up to 12 kept on the Rhino; dimmed so panels stay readable), a text colour, and typefaces for titles, subheadings and regular text; each is kept with the theme, for day and night. The 3D view slider sets how see-through the bed is from below, for seeing support marks.

Whatever the theme, Stop and a live panel stay red, and the big numbers, positions and console keep their own fonts. A shared theme file names its picture but doesn't carry it, so on another Rhino it shows the plain page colour.

Machine

  • Connection: where this screen finds Moonraker and the Portal. Leave the boxes blank when Studio is opened from the Rhino.
  • Trusted addresses: which screens Moonraker lets in, the same list Mainsail uses.
  • Tool changing: how this machine changes tools and how Studio reads which one is mounted (on the Rhino, SWAP_TOOL).
  • Cameras: the camera list Moonraker keeps for every screen; add, edit, turn off or delete a camera.
  • Slice profiles: your slicing settings, saved on the Rhino, so a cleared browser or a new host keeps them. Rename, export, import, or go back to an earlier version with History.
  • Your macros: short routines built from steps, saved on the Rhino and run from Control › Macros. New macro, or Add the starter macros (park, heat for PLA, cool down). What it sends now shows the G-code for the machine as it is, or why it can't run. A macro is refused during a job, with the wrong or unconfirmed tool, with an axis not homed, or past the travel limits.

System

  • Software: every package on the host, its version and the latest, with Update for each and Update all. Updates are refused while a job runs; Update all runs them in order and restarts each service once. The Rhino Tool Manager, with the Rhino Studio inside it, updates from here too.
  • Network: how this screen reaches the Rhino, and the Rhino's own network: Wi-Fi or Ethernet, fixed or automatic address. A network change switches back by itself when its time runs out, unless you keep it, so a mistake can't lock you out.
  • Host: restart Klipper, its firmware or a service; reboot or shut down the host; the Rhino's name on the network; and Backups (see Files, backups and tests). Nothing here runs during a job.
  • Logs: Klipper's and Moonraker's logs, with the last error picked out. About: the Studio version, its credits, and the style guide.
